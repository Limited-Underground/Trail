# OT-128 Monocypher second corrective-retry execution abort

**ABORT RECORDED — every benchmark-touched node was restored to exact Trail; no Monocypher benchmark result admitted.**

Both anonymous nodes passed exact installed-Trail application readback before any benchmark write. Node A received and readback-verified the exact application-only benchmark image, but capture did not validate. Node A was then restored, readback-verified, and reset to the exact Trail image. Node B was never benchmark-written and required no restore. The private execution receipt reports `restoration_complete=true`.

After the receipt was verified, a separate non-writing hard reset succeeded on both devices and both USB endpoints returned. The owner had not yet provided a post-abort visual confirmation when this record was prepared, so this checkpoint makes no post-abort display claim.

The private receipt does not retain raw capture bytes or a safe failure category, so it cannot distinguish endpoint re-enumeration, a read exception, partial input, incomplete frames, or semantic parser rejection. The physical root cause is not confirmed. A source-level audit nevertheless found corrective gaps: the one-shot firmware stream has no start-ready handshake, the host rejects a partial line rather than accumulating bytes across its 250 ms timeout, and a fixed re-enumeration sleep substitutes for verified endpoint disappearance and return. Another timing-only retry is not authorized.

Decision 0066's one-time authority is consumed by this abort and is not reusable. Any future attempt requires a corrected, tested, hash-bound firmware/runner pair and a fresh published one-attempt authority. The private journal and execution receipt remain retained unchanged and unpublished.
