# OT-165 Android initial system-bond coordinator

**Date:** 2026-08-30

**Result:** Host-validated Android production pairing coordinator accepted;
physical phone and durable device ownership remain open

## Implemented boundary

The Android production Bluetooth facade now binds one initial system-bond
attempt to the exact selected opaque endpoint token and one monotonic facade
generation. An already bonded exact candidate may continue to GATT. A fresh
candidate uses Android's `createBond()` flow and a dynamically registered
bond-state receiver; the attempt must observe `BOND_BONDING` before the exact
device's `BOND_BONDED` callback can continue to GATT.

The application never intercepts a pairing request and has no PIN/passkey
setter, callback, field, display, log, or persistence path. Android's system UI
is the exclusive phone-side passkey-entry surface.

Cancellation or failure, permission loss, timeout, lifecycle close,
disconnect, callback mismatch, and a bonded callback without this attempt's
bonding transition all terminate fail-closed. Synchronous receiver,
timer, or `createBond()` start failures emit a terminal typed event before the
lease returns false; the runtime therefore cannot overwrite that result with a
transient connection failure or schedule an automatic pairing retry.

## Admission boundary

This evidence accepts the Android software path for one bounded initial system
bond. It does not prove durable NimBLE bond persistence, one-phone ownership,
saved-bond reconnect, replacement, old-bond removal, target protected GATT,
physical Android pairing, signed installation, bidirectional messaging,
supported hardware, field readiness, or release readiness. Android remains
60%; V1 remains exact 43.75% and displayed 44%.
