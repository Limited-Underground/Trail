# OT-164 two-node fresh BLE pairing-window acceptance

**Date:** 2026-08-29

**Result:** Corrected application installed and independently verified on both
anonymous Heltec V4 bench nodes; local pairing-window behavior physically
accepted

## Build and correction

Two independent ESP-IDF v6.0.2 builds produced the identical corrected
507,296-byte application with SHA-256
`69ae6546724d2ebbd6a3b8a133d1fc267383839c632b3b73e6a1ca72abf4678a`.
The target uses GPIO0 as an active-low local input with boot-release arming,
40 ms debounce, a minimum 3000 ms hold, and release. A window contains one
fresh rejection-sampled six-digit candidate for exactly 30,000 ms. The OLED
shows `PAIR` and centered digits, restores the compact footer on ordinary
closure, and powers down the display path if pairing rendering or footer
restoration fails.

The earlier 507,168-byte V0 application was installed and exactly read back on
both nodes, then rejected before owner acceptance when review found the missing
emergency concealment path. Its authority is consumed by abort and cannot be
reused. The V1 authority is separate and inherits no attempt.

## Corrected hardware execution

Before any V1 write, both anonymous nodes independently read back the exact
installed 507,168-byte V0 application. Each node then received exactly one
application-only write at offset `0x10000`. Both independent readbacks matched
the corrected 507,296-byte application, and both nodes returned to the running
display after reset. No bootloader, partition table, OTA data, NVS, fuse,
radio, or phone operation occurred, and no recovery write was required.

The V1 authority is consumed by success, non-reusable, and grants no
continuation.

## Owner acceptance

The owner completed the same bounded checks on both devices without reporting
or recording either PIN value:

- a short BOOT/USER press did not open the pairing window;
- holding for at least three seconds and releasing showed `PAIR` plus exactly
  six digits;
- the pairing display disappeared after approximately 30 seconds; and
- reopening the window and pressing reset left the PIN concealed after reboot.

This visual timing check corroborates the exact 30,000 ms firmware contract; it
is not instrument-grade timing evidence.

## Admission boundary

This result proves the corrected target-side local input, six-digit display,
timeout concealment, reset concealment, exact two-node application installation,
and readback. It does not prove Android pairing or passkey entry, Bluetooth
bond ownership or persistence, reconnect, replacement, protected-GATT
authority, authenticated messaging, supported hardware, end-to-end operation,
field readiness, release readiness, or regulatory acceptance. V1 remains exact
43.75% and displayed 44%.
