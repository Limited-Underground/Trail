## Static compatibility finding

The exact accepted generated sdkconfig remains publicly pinned at 106,913 bytes
and SHA-256
`4260688e6323cfda7a50912b4cc9c77a7b6f5133b6970b543bf0ce822ffd023f`.
The frozen public build inputs select USB Serial/JTAG as the ESP-IDF console and
INFO as the default log level. The accepted benchmark application suppresses
runtime logs only in `app_main`, then installs the direct USB Serial/JTAG driver
and starts the task that waits for exact START before emitting exact READY.

The frozen runner opens the same endpoint, sends START once, and immediately
reads. When two full chunks are already available, neither an empty-read sleep
nor the 250 ms START retry occurs before the preamble budget is crossed. The
confirmed contract-level cause is therefore that already queued startup bytes
and post-START control preamble share the same 512-byte host budget; the runner
can abort before the application control driver accepts START.

The physical OT-137 byte contents were not retained and remain unconfirmed.
This finding does not label them as boot logs.
