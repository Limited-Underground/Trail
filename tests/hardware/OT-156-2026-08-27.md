# OT-156 reset-aware Noise XK radio host correction

**HOST-ONLY CORRECTION — no device, phone, firmware build, flash, reset, radio
transmission, cryptographic measurement, or physical observation occurred.**

## Problem boundary

The consumed OT-155 attempt retained only the safe terminal category
`radio_run_failed`. It did not retain an exact physical failure substage and
does not prove a host, USB, firmware, or radio root cause.

Host inspection found that the immutable OT-153 runner accepted a firmware
`RESTART` receipt and then waited for post-reboot receipts through the same
serial handle. Adversarial Windows-style simulation invalidates that handle
when restart is accepted: the frozen runner fails, while the OT-156 successor
succeeds only after opening one fresh handle per anonymous node. This proves the
successor contract and the old host assumption; it does not rewrite OT-155 as a
proven USB-reconnect failure.

## Accepted successor behavior

1. Validate anonymous node A's restart acknowledgement.
2. Validate anonymous node B's restart acknowledgement.
3. Close and discard A's obsolete handle, settle for 150 milliseconds, and
   retry a fresh open every 250 milliseconds for no more than 15 seconds.
4. Apply the same bounded reopen to B.
5. Before each open, set DTR and RTS false and restore the private port onto the
   fresh serial object. Initial opens are independently bounded to 10 seconds.
6. Admit no stale queued receipt from either old handle.
7. Require both nodes' complete stale-self-test, boot, profile, status,
   command-list, and explicit profile-echo contract before `prepare`, `arm-tx`,
   `send`, `abort`, or `end` is issued.
8. Preserve the frozen successful protocol/result behavior exactly. With fixed
   tokens, the successor result bytes, full command order, command count, and
   per-verb counts equal the frozen OT-153 happy path.
9. Report failures only through sixteen allowlisted stage codes with no private
   port, path, serial, backend, device, or nested exception text.
