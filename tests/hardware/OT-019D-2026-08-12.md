# OT-019D Privacy-Safe Windows USB Discovery Snapshot

Date: 2026-08-12

Evidence class: bounded connected-bench discovery

Result: pass for discovery and fail-closed behavior; three candidates were
enumerated and none was authorized for flashing

## Setup

The development laptop had the following assembled devices connected:

- two Heltec V4 OLED GPS bundles running MeshCore USB Companion; and
- one packaged SenseCAP Solar Node P1-Pro running MeshCore Repeater.

These Heltecs are bench clients, not the board-level parts planned for the
first complete touchscreen client. The SenseCAP remains the packaged solar
repeater candidate.

## Method

`tools/Get-OpenTrailUsbCandidates.py` used pySerial's read-only Windows port
enumeration and selected only the two observed USB runtime families. The
default snapshot did not open a serial session and omitted local ports, serial
numbers, hardware-instance paths, device locations, and raw enumerator data.

No firmware, settings, radio state, GNSS state, identity, USB mode, boot mode,
or recovery state was changed.

## Result

| Runtime family | Candidates | Inspection available | Flashing allowed |
| --- | ---: | --- | --- |
| Seeed TinyUSB serial (`2886:0059`) | 1 | yes | no |
| Espressif application USB (`303A:0002`) | 2 | yes | no |

Every candidate explicitly marked USB identity as non-authoritative for
flashing and retained unresolved low-level processor/memory, exact profile,
target role, received revision, and bootloader evidence.

## Interpretation

This proves that the first Windows discovery layer can find all three current
bench runtimes without leaking persistent hardware identity and without
accidentally enabling Flash. It does not prove exact board identity, processor,
memory, RF variant, bootloader/partition layout, firmware-image compatibility,
or recovery behavior. The pure firmware-install preflight and all of its
remaining gates still apply.
