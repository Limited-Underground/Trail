# OT-019D Privacy-Safe Windows USB Discovery Snapshot

Date: 2026-08-12

Evidence class: bounded connected-bench discovery

Result: pass for discovery, redacted runtime identification, and fail-closed
behavior; three candidates were inspected and none was authorized for flashing

## Setup

The development laptop had the following assembled devices connected:

- two Heltec V4 OLED GPS bundles running MeshCore USB Companion; and
- one packaged SenseCAP Solar Node P1-Pro running MeshCore Repeater.

These Heltecs are bench clients, not the board-level parts planned for the
first complete touchscreen client. The SenseCAP remains the packaged solar
repeater candidate.

## Method

`tools/Get-OpenTrailUsbCandidates.py` used pySerial's read-only Windows port
enumeration and selected only the two observed USB runtime families. The
default discovery snapshot did not open a serial session. A separate
`tools/Get-OpenTrailRuntimeEvidence.py` pass then issued only MeshCore version,
board, and runtime-role queries. Strict parsers reduced replies to allowlisted
board family, firmware/build, protocol version where available, and installed
runtime role.

Both outputs omitted local ports, serial numbers, hardware-instance paths,
device locations, raw enumerator data, raw replies, pairing data, and device
identity. Unexpected values fail with only an error type and are not echoed.

No firmware, settings, radio state, GNSS state, identity, USB mode, boot mode,
or recovery state was changed.

## Result

| Runtime family | Candidates | Redacted runtime result | Flashing allowed |
| --- | ---: | --- | --- |
| Seeed TinyUSB serial (`2886:0059`) | 1 | Seeed SenseCAP Solar / MeshCore repeater / `v1.16.0-07a3ca9` | no |
| Espressif application USB (`303A:0002`) | 2 | Heltec V4 OLED / MeshCore companion / `v1.16.0-07a3ca9` | no |

Every candidate explicitly marked USB and runtime identity as non-authoritative
for flashing and retained unresolved low-level processor/memory, exact profile,
OpenTrail target role, received revision, and bootloader evidence.

## Interpretation

This proves that the first Windows inspection layers can find and meaningfully
label all three current bench runtimes without leaking persistent hardware
identity or accidentally enabling Flash. Current installed runtime role is not
permission to install a bench-client, complete-client, or packaged-repeater
OpenTrail image. This does not prove exact board identity, processor, memory,
RF variant, received revision, bootloader/partition layout, firmware-image
compatibility, or recovery behavior. The pure firmware-install preflight and
all of its remaining gates still apply.
