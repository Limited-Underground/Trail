## Deterministic host-only diagnosis

Exact byte accounting leaves no partial record:

- control `READY`: 16 bytes;
- header: 309 bytes;
- `psa_crypto_init` pass gate: 196 bytes;
- `primitive_vectors_and_negative_cases` fail gate: 217 bytes;
- runtime resources: 454 bytes; and
- terminal failure: 276 bytes.

The total is exactly 1,468 bytes. The firmware control flow emits those five
frames only when initialization passes and the aggregate primitive-vector gate
fails before sampling. The host runner retained the five complete frame lines
but waited to the 180-second deadline because the frozen success parser is
invoked only at exactly 1,015 frames.

Source and frozen-ELF inspection then located the exact failing condition. The
all-zero X25519 peer correctly returns `PSA_ERROR_INVALID_ARGUMENT`. The pinned
TF-PSA error path deliberately overwrites the allocated output with random bytes
and sets `output_length` to the full 32-byte output size. The benchmark fixture
incorrectly required that undefined error-output length to equal zero. Frozen
ELF disassembly confirms the status comparison passed and the nonzero
`output_length` comparison alone branched to failure.

## Host-only correction

Every OT-150 source and executable binding remains immutable. A separate OT-151
successor target removes only the invalid `output_length == 0` requirement,
keeps the mandatory `PSA_ERROR_INVALID_ARGUMENT` check, and retains failure-
buffer zeroization. Focused regression checks fail if the status requirement is
removed or if the old length assertion returns.

A separate successor failure parser and runner recognize only canonical early
terminal failure shapes and return a privacy-safe
`benchmark_reported_failure` immediately. Tampered order, gate identity,
outcomes, missing or extra resource records, noncanonical JSON, early success,
or trailing bytes still fail closed. The strict successful transcript remains
exactly 1,015 frames; no timeout, count, parser, or result-admission boundary is
weakened.
