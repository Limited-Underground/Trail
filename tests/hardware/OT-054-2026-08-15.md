## Scope

OT-054 adds the fixed 32-byte `OAP0/v0` durable owner/tombstone record and an
adapter from the accepted one-phone authorization authority to an injected
protected store. The store contract requires a fresh expected-generation
comparison, atomic publication of the complete record plus an independently
rollback-resistant generation floor, and exact readback. A pre-write failure
may report `failed`; every post-write ambiguity must report `uncertain` and
latch authorization closed. The record CRC is format/corruption detection
only, never authenticity or rollback protection.

The private bond-binding resolver accepts only an opaque 16-byte reference and
nonzero generation allocated by a trusted private bond store. A separately
provisioned device-secret PRF maps that private input to the stable opaque
128-bit controller token. No public BLE address, public identifier, peer value,
or raw key enters the record or PRF interface. Re-pairing must allocate a new
private reference or advance the private bond generation. Scratch input and
derived bytes are explicitly cleared on success, failure, not-ready, and
reentrant exits.

The target admission distinguishes configuration from verified runtime proof.
`CONFIG_NVS_ENCRYPTION` and the HMAC-key-protection configuration can at most
show configuration intent; they do not prove a protected partition was
initialized or that an eFuse key is provisioned, read-protected, and usable.
The current generic target has NVS encryption disabled and has no private bond
store, separate PRF key, atomic record/floor backend, or independent rollback
floor, so preflight deterministically returns
`nvs_encryption_not_configured` and runtime remains disabled.

## Physical/runtime boundary and next gate

The target self-check uses only fixed in-memory fakes. Target production code
does not open NVS, access eFuse/HMAC state, resolve a real bond, initialize the
NimBLE host/controller, register the service, advertise, or mutate persistent
state. No target was selected, opened, erased, written, flashed, reset, or
rebooted by OT-054. The image remains the unsupported generic 2 MB ESP32-S3
candidate.

The next hardware/provisioning gate must define and verify a protected NVS
partition, independently protected monotonic generation floor, private bond
reference lifecycle, separate HMAC_UP PRF key with provisioning/read-protection
proof, and atomic compare/commit/readback backend. Only after that gate can the
real persistence/binding adapters be injected and BLE startup be reconsidered.
