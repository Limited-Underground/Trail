# OT-070 Protected-Storage Partition Transition Admission Evidence

Date: 2026-08-17

## Scope

OT-070 adds a pure host admission guard and a design-only Heltec transition
manifest for the exact `OTHP0/v0` to `OTPS0/v0` partition split. It does not
change the active target configuration or perform device access.

## Accepted evidence

- Thirteen strict C++ scenario groups pass with warnings treated as errors and
  pass 100 repeated executions.
- Fresh installed-layout, source-region/migration, recovery, and authority
  evidence must share one nonzero operation ID and evidence-set ID, retain
  nonzero generations, and bind exact source/candidate/recovery digests.
- Five focused manifest groups bind the exact source and candidate CSV hashes,
  rows, offsets, sizes, flags, and 16 MiB boundary; require an exact future
  all-`0xFF` 1 MiB source proof; enforce phase-specific restoration policy;
  and verify zero command, port, capability, or authority surface.
- The existing Heltec target admission remains green at 9/9 groups.
- The guard admits only exact installed-layout readback, verified blank media
  or a separately verified semantic migration, exact recovery artifacts and
  ROM route, no runtime/key/eFuse/other-flash request, and one exact
  operation-scoped partition-only authority.
- Unknown enum values, absent or mismatched layout evidence, contradictory
  source evidence, missing recovery evidence, broader operations, missing or
  mismatched authority, and improper authority scope fail closed in a fixed
  order.
- The implementation exposes no filesystem, device, flash, NVS, key, eFuse,
  logging, or execution API.

## Current target boundary

- Active `partitions.csv`, `sdkconfig.defaults`, target contract, CMake,
  runtime composition, installed image, and physical device are unchanged.
- The design-only manifest remains `DENY`; source-region evidence is not
  captured and all transition capabilities and authorities are false.
- The accepted OT-061 partition-table hash makes the proposed source layout
  plausible, but later app-only writes do not establish the current installed
  table or source-region contents. OT-070 records neither as physical fact.
- No NVS encryption, protected key, independent rollback floor, private bond,
  GATT authorization, Ready state, or physical transition is accepted.

## Remaining gates

Before a physical transition: prove exact installed table and blank/source
disposition without retaining contents; preserve exact recovery artifacts;
accept a separately scoped one-shot write plan; and verify the candidate table
and recovery on the selected unit. Key provisioning, rollback-floor
provisioning, runtime injection, first authorization record, and GATT admission
remain separate later phases.

Historical V1 remains exactly 31.75% and displays as 32%; this admission guard
does not complete a V1 milestone.
