## Scope

OT-052 adds a fixed-memory, externally serialized callback adapter above the
accepted OT-050 provisional authorization lifecycle. The adapter binds one
exact registered Protocol Info, Command, Stream value, and independently
discovered Stream CCCD handle; one connection and monotonic transport
generation; fresh encrypted/authenticated/bonded/key-size/MTU evidence; one
private trusted bond/controller binding; one session; and one immutable
submission-era indication tuple.

The dormant real NimBLE v6.0.2 surface now defines protected v0.1 Protocol Info
Read, protected Command Write With Response, and protected Indicate-only Stream
access. Both the AUTHOR callback and actual Protocol Info/Command access
callback re-read current NimBLE connection security. Encryption or a key below
16 bytes maps to ATT Insufficient Encryption; missing authentication or bond
maps to ATT Insufficient Authentication; private-binding, session, attribute,
subscription, or lifecycle denial maps to ATT Insufficient Authorization. A
successful exact 20-byte protected v0.1 Protocol Info read is therefore
device-enforced restricted-path evidence; bond state alone is not.

Before application authorization, only Protocol Info and the exact
authorization claim kinds can pass. Claim responses require exact Stream
indication subscription and MTU at least 51. The target reserves real mbuf
capacity before lifecycle or authority mutation. Pending must be confirmed
before the exact physical-decision seam can resolve authority, and promotion
occurs only after exact Accepted/Replaced terminal confirmation. Normal
snapshot/action traffic stays denied before promotion.

Registration captures service/characteristic value handles and separately
discovers the generated Stream CCCD through `ble_gatts_find_dsc`; no `+1`
handle inference exists. Connection, security, MTU, subscription, AUTHOR,
indication completion, timeout, and disconnect callbacks route through the
single serialized adapter. Every submitted indication retains its exact
connection, transport generation, session, exchange, Stream value handle, and
delivery token. The pinned NimBLE admission verifies active indication failure
is delivered before the application disconnect callback, so a callback from an
old connection cannot be relabeled after connection-handle reuse.

## Physical/runtime boundary and next gate

`app_main` does not call the registration function, initialize the NimBLE host
or controller, advertise, or inject trusted bond/persistence/physical-input
authority. The callback code is compiled and link-retained but is not installed
or run. No target was selected, opened, erased, written, flashed, reset, or
rebooted. The full repository harness did execute its pre-existing privacy-safe
Windows USB candidate inventory; that read-only inventory is not OT-052
runtime evidence. The image remains the unsupported generic 2 MB ESP32-S3
candidate.

A later increment must inject the accepted persistent owner authority and
physical-presence decision source, start the exact controller/host/service and
advertiser under a separately reviewed board gate, then validate one real
bonded Android connection. Until then there is no live GATT, authorization,
radio, or delivery proof.
