# OT-065 Reversible Protected Authorization-Store Foundation

Date: 2026-08-17

## Accepted scope

OT-065 adds one backend-neutral coordinator that implements the existing
`CompanionAuthorizationProtectedStore` contract over exact two-slot record
media and a separately injected monotonic generation floor. It also records an
inactive Heltec candidate partition/provisioning plan. No target runtime,
partition table, sdkconfig, device, or irreversible key state changed.

## Host evidence

The focused strict C++17 warnings-as-errors build compiled:

- `companion_authorization.cpp`;
- `companion_authorization_persistence.cpp`;
- `companion_authorization_protected_store.cpp`; and
- `companion_authorization_protected_store_tests.cpp`.

All twelve deterministic groups passed. They cover:

- empty first boot and exact floor-matched restore;
- inactive-slot rotation and reboot reconciliation;
- prepare, exact readback, floor advance, and final reread ordering;
- zero-floor media, prepared-ahead, stale-only, missing-current,
  duplicate-current, corrupt, and conflicting state;
- invalid generation and record rejection before media access;
- safe pre-write failure versus ambiguous applied writes;
- inexact prepared readback with no floor advance;
- floor conflict, failure, uncertainty, and wrong readback; and
- final floor, record corruption, or disappearance after advancement.

The Heltec target-only admission suite passes eight groups. It proves the exact
candidate files remain inactive, select no protected key IDs or rollback-floor
provider, enable no runtime capability, and grant no partition/application/
erase/device-write authority. It also verifies the active partition table,
sdkconfig, storage capability, and storage authority remain unchanged.
