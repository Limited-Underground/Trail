# OT-009A Recoverable Three-Node Soak Qualification

Date: 2026-08-09

Status: in progress; recovery and short smoke gates passed, long-duration bench
soak not yet complete

## Purpose

Qualify a low-duty, checkpointed three-node MeshCore soak before leaving it
unattended. The test uses the two Heltec USB Companions as endpoints and reads
the Seeed SenseCAP repeater console without changing its role or radio
configuration.

The harness persists only redacted counters, port labels, a temporary channel
slot/name, and aggregate delivery observations. The randomly generated channel
secret and message markers remain in memory. Device identities, public keys,
coordinates, PINs, and serial numbers are not recorded.

## Starting health

- Both Heltecs independently reported MeshCore USB Companion
  `v1.16.0-07a3ca9`, the matching 910.525 MHz / 62.5 kHz / SF7 / CR5 profile,
  zero core and receive errors, and empty queues.
- The SenseCAP reported `Seeed SenseCap Solar`, MeshCore Repeater
  `v1.16.0-07a3ca9`, the same modulation profile, 22 dBm configured transmit
  power, repeat enabled, zero core/receive errors, and an empty queue.
- All devices remained USB-connected with antennas attached as previously
  confirmed by the owner.

## Channel lease and recovery design

`tools/meshcore_channel_lease.py` now creates an atomic non-secret journal
before the first channel write. It records both port labels, the selected empty
slot, and a random recognizable channel name. It deliberately does not record
the 16-byte channel secret.

Cleanup reads the recorded slot on each device and clears it only when it is
already empty or still has the exact leased name. A different name fails closed
and is never erased. A journal remains until both devices verify an empty name
and zero secret. Four fake-node host groups cover normal cleanup, a write that
applies before its response is lost, mismatched-slot preservation, malformed
journal rejection, and overwrite refusal.

## Real uncertain-lifetime recovery proof

The two Heltecs were given one ephemeral private channel in their shared empty
slot. Both serial sessions were then intentionally disconnected without normal
cleanup, modeling a stopped test process. Recovery-only mode reconnected from
the retained journal, matched the exact leased channel, cleared and verified
both nodes, and removed the journal. Result: 2/2 cleanup confirmations, no
persisted secret, and no remaining lease journal.

## Short traffic qualification

A first bounded run sent two private-channel markers in each direction:

- 4/4 delivered, zero loss, zero duplicates;
- latency range 232.4-248.6 ms;
- observed SNR range 6.75-12.75 dB;
- zero new companion core/receive errors and both queues empty; and
- both temporary channel slots and the journal verified removed.

During that close-range sample, the SenseCAP recorded +3 flood RX and +3 flood
TX for four endpoint transmissions while all four endpoint messages still
arrived. This is expected to be measured rather than assumed: a nearby
destination can receive an original directly, and one redundant repeater copy
may be missed or suppressed without endpoint loss.

The dedicated soak harness then ran a two-direction smoke cycle:

- 2/2 delivered, zero loss, zero duplicates;
- 240.1 and 240.6 ms latency;
- 11.5-12.25 dB received SNR;
- exactly +2 flood RX and +2 flood TX at the repeater;
- zero new errors and empty endpoint/repeater queues; and
- repeat remained enabled before and after, with verified channel/journal
  cleanup.

All 18 existing C++ host suites plus the new channel-lease suite passed before
the hardware smoke cycle.

## Long-duration gate

The prepared long run uses one alternating marker per conservative interval,
redacted JSON checkpoints after every probe, repeater checkpoints every ten
probes, final endpoint/repeater counter deltas, and the same verified cleanup.
It succeeds only with no loss/duplicates, no new core/receive errors, empty
cleanup on both endpoints, and repeat still enabled.

No long-duration result is claimed in this revision. This document will be
updated only after the run completes and its final checkpoint plus device state
are inspected.

## Evidence boundary

This qualifies the harness and crash-recovery mechanism on the current close
bench. It does not establish field range, obstruction, mobility, congestion,
long-term solar/battery endurance, regulatory compliance, a direct SX1262
OpenTrail binding, or production reliability.
