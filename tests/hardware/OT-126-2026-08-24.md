# OT-126 Monocypher corrective-retry execution abort

**ABORT RECORDED — no Monocypher benchmark result admitted; both devices are restored and visibly running Trail.**

Both anonymous nodes passed exact installed-Trail application readback before any benchmark write. Node A received and readback-verified the exact application-only benchmark image, but its fresh serial capture ended before the firmware's first possible frame. Node A was then restored, readback-verified, and reset to the exact Trail image. Node B was never rewritten.

The root cause is deterministic in the accepted OT-125 runner: the benchmark task intentionally waits 3,000 ms before its first frame, in addition to normal boot and USB startup, while a fresh capture cycle gives up after eight 250 ms empty reads, at most 2,000 ms. The capture therefore closed before an admissible first frame could exist. No frame, primitive, timing, runtime-resource, or comparative result is admitted.

The installed-application preflight used esptool with `--after no-reset`. Because Node B was not benchmark-touched, the abort restoration path did not reset it. A separate non-writing hard reset was therefore applied to both nodes after receipt verification. Both USB endpoints returned, and the owner then observed both Trail displays on. This is a successor-runner defect to close; it is not evidence of a firmware or display timeout.

Decision 0064's one-time authority is consumed by this abort and is not reusable. Any further attempt requires a fresh authority and a new runner that preserves a sufficient first-frame grace period, fixes all-device preflight reset, and prevents an operator-shortened capture contract. The private journal and execution receipt remain retained unchanged and unpublished.
