# OT-063 read-only protected-storage admission probe

Date: 2026-08-16

Status: `HOST-TESTED-BUILD-LINKED-NOT-RUN`; `NOT-FLASHED`

## Purpose

OT-063 replaces the Heltec target's compile-time protected-storage placeholder with a typed, target-local, read-only ESP-IDF admission probe. It is a prerequisite only: it observes whether the configured target could later satisfy protected-storage admission, but it does not provision, initialize, open, write, erase, or authorize storage.

The currently pinned target configuration remains fail-closed at `nvs_encryption_not_configured`. That first gate returns before the target port performs any partition or eFuse/HMAC read. Even an injected all-positive observation remains denied at the later `protected_nvs_not_verified` gate because a usable protected backend, private bond store, separately protected PRF key, atomic record/floor backend, rollback floor, and runtime injection remain absent.

## Exact read-only boundary

The target-neutral probe can observe only:

- configured NVS-encryption and HMAC-key-protection selections;
- presence of the named NVS partition;
- a selected HMAC key identifier in the bounded range 0 through 5;
- `HMAC_UP` purpose and read protection for that selected key;
- one private operational HMAC calculation over a fixed, non-secret domain message.

The HMAC message and output buffers are explicitly zeroized. Results are reduced to typed errors and coarse booleans/enums. The implementation does not initialize NVS, open a namespace, generate keys, write or erase NVS, program eFuses, expose key material or identifiers, mutate authorization state, or change the GATT/runtime path.
