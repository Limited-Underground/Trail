## Result

The Heltec V4 bench target now fails closed around the evidence-bound OT-DEV-001 memory profile and the versioned `OTHP0/v0` recovery-aware partition layout. The target builds reproducibly with pinned ESP-IDF v6.0.2, but this result grants no hardware-write, updater, OTA, recovery, or storage authority.

No simulator file or simulator test was inspected, edited, or run. No serial port was opened, no hardware was accessed, and no image was flashed. ESP-IDF printed its standard post-build flash suggestions; none was executed.

## `OTHP0/v0` partition layout

The source CSV and generated binary were both checked with the pinned ESP-IDF partition parser. The independently decoded binary was:

| Name | Type/subtype | Offset | Size |
|---|---|---:|---:|
| `otadata` | `data/ota` | `0x009000` | `0x002000` (8 KiB) |
| `factory` | `app/factory` | `0x010000` | `0x4f0000` (5,177,344 B) |
| `ota_0` | `app/ota_0` | `0x500000` | `0x500000` (5,242,880 B) |
| `ota_1` | `app/ota_1` | `0xa00000` | `0x500000` (5,242,880 B) |
| `ot_state` | application-defined `0x40/0x00` | `0xf00000` | `0x100000` (1 MiB) |

The rows are non-overlapping, both OTA-capable slots are equal, the factory slot is intentionally 65,536 bytes smaller than either OTA slot, and `ot_state` ends exactly at `0x1000000` (16 MiB). There is no ordinary NVS or PHY partition. `ot_state` is reserved and unopened; capacity does not grant storage authority. No updater or OTA state machine exists.
