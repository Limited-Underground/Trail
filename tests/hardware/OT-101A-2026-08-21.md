OT-101A adds a pure target-neutral adapter layer between two existing host
contracts and the accepted OT-101 compact footer. It consumes
`power::PowerAssessment` and `companion::CompanionBleRuntimeStatus`; it owns no
source, clock, identifier, logger, transport, or persistent state.

For a present battery with a valid percentage from 0 through 100, normal, low,
and critical assessments become a valid footer metric. The adapter reconstructs
the original observation time as `assessment_now_ms - age_ms`. A separate
`render_now_ms` controls footer freshness, so delayed composition preserves and
expires the old sample instead of making it fresh. Render time before assessment
time fails closed.

Unavailable or external-only states, missing battery data, and a source that is
not ready become unavailable. Fault, stale, invalid, other assessment errors,
out-of-range percentages, and age greater than `assessment_now_ms` fail closed
as invalid.

BLE mapping is deliberately small and exhaustive for the current runtime
contract:

| Runtime phase | Footer code |
| --- | --- |
| dormant | `-` |
| waiting for host synchronization | `S` |
| advertising | `A` |
| connected | `C` |
| restart wait | `R` |
| contained | `E` |

Any terminal runtime error takes precedence and maps to `E`; an unknown phase
without a terminal error fails closed to `-`. Connection handles, restart
tokens, attempts, authorization flags, and other runtime details do not affect
the compact output.

Composition intentionally supplies no GNSS-satellite observation and uses an
unsupported activity owner. Every tested composition therefore renders
`GPS:--` and keeps
the five-column arrow field blank. This does not weaken the separately tested
OT-101 injected-event contract; it proves only that these adapters do not
invent GPS or radio activity.

Ten focused C++17 warnings-as-errors scenario groups pass. They cover battery
states, presence, validity, 0/100 boundaries, every defined assessment error,
assessment-time reconstruction, delayed expiry, regressive-clock rejection,
unsigned boundaries, all six BLE phases,
terminal-error precedence, unknown phases, exact integrated formatting, field
isolation, permanent GPS unavailability, blank activity, determinism,
statelessness, and independence from identifiers. The existing twelve footer
groups also remain green. The authoritative corrected complete host gate passed
with exit
zero in session 17704.

The adapters remain under `tests/host_support`, outside the firmware tree.
There is no target renderer or OLED driver, battery sensor binding,
GNSS-satellite source, BLE transport binding, radio-event source, or accepted
real-traffic source. No firmware or target build, device access, flash,
telemetry, traffic, physical-display, support, compatibility, regulatory, or
V1 score evidence follows from this increment.
