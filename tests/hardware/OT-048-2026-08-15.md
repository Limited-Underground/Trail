## Scope

OT-048 adds three known `OTC0/v0` frame kinds to the shared companion protocol
decoder: client-to-device Claim Start `0x03`, device-to-client Pending `0x84`,
and device-to-client terminal `0x85`. It also makes the existing semantic
dispatcher and normal application-authorized coordinator explicitly reject
those authorization kinds. The generic `heltec_v4_bench` candidate already
links all three touched shared sources, so it was rebuilt with the pinned ESP-
IDF toolchain.

The new `companion_authorization_wire.cpp` codec and provisional response
tracker are not listed in the target CMake source set and are absent from the
link map. No target path admits the three authorization kinds, starts a
provisional session, changes application authorization, or reaches device
authority. Current Protocol Info has no authorization-claim capability bit and
the callable NimBLE Command path remains denied.
