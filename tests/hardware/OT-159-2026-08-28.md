## Deterministic host-only diagnosis

The inherited OT-153 adapter verifies an application readback by calling
`coordinator._sha256(readback)` with a byte string. OT-157 substitutes its
successor coordinator into that adapter. The successor exports a same-named
file-hash helper whose parameter is a `Path` and whose implementation calls
`path.read_bytes()`. That public helper shadows the inherited byte-hash helper,
so the official composed preflight rejects the already matching readback.

The exact source identities are:

- OT-157 coordinator SHA-256:
  `a17d4615a50d2e373ba7fab98b6bed160e6b24e291aac2ec83f0fa19d1479db1`;
- OT-157 adapter SHA-256:
  `ec744f7430627600de1491d5729d8b5874ac38977faa786df90a4d39ce2d3de8`;
- OT-156 runner SHA-256:
  `81d0a329d34c20e76362b9a3f07221b77b77f02189dd06660119a02ac1700244`;
- OT-156 serial runtime SHA-256:
  `bcdb1a772971aa665be699c2699a2b69625c4e8bd2352abd21811be0a4295dd8`.

This proves a host-composition defect only. It does not establish a device,
USB, firmware, antenna, or physical-radio defect.

## Authority and next gate

No irreversible consumption boundary was crossed, so the OT-158 authority
remains unused and unconsumed. It is still non-reusable and grants no
continuation; because it binds the defective immutable OT-157 composition, it
cannot be transferred to corrected host code.

OT-160 is the minimal host-only successor correction. It must separate the
file-hash and byte-hash helpers, prove the real composed preflight path, and
preserve every existing fail-closed and privacy boundary. Later work must freeze
the exact corrected bundle and accept fresh non-reusable authority before any
corrected device attempt.
