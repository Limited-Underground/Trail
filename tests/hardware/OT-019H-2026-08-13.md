# OT-019H source-free Windows runtime-identification proof — 2026-08-13

## Scope

This record covers the inspection-only Windows device utility with the three
assembled bench units attached to the development laptop:

- two Heltec V4 OLED devices running MeshCore USB Companion; and
- one SenseCAP Solar device running MeshCore Repeater.

It does not cover firmware selection, erase, write, recovery, exact received
board revision, radio-band qualification, or an OpenTrail compatibility claim.

## Method

The acceptance path used only code compiled into the self-contained Windows
application. It did not use Python, MeshCLI, CIM/WMI, a shell command, or a
network service.

The application:

1. enumerated present Windows Ports-class devices through SetupAPI;
2. privately matched only the two approved USB-family identifiers;
3. retained each validated local serial endpoint only inside the inspection
   process;
4. sent the fixed MeshCore companion app-start/device-info request or the fixed
   repeater `board`, `ver`, and `get role` requests; and
5. reduced replies to allowlisted model, role, and firmware display values.

The companion parser deliberately skipped the private BLE-PIN bytes rather
than decoding or retaining them. No arbitrary serial command, reset, reboot,
bootloader, line-toggle, erase, or write surface was exposed.

## Result

The built-in C# path reported:

`3 USB candidates found · 3 runtime-identified · 0 ready to flash`

The reduced result contained two Heltec V4 OLED companions and one SenseCAP
Solar repeater. All three reported the installed MeshCore runtime
`v1.16.0-07a3ca9`. Every candidate remained blocked from Flash.

The first native attempts timed out because the serial line state did not match
the proven USB CDC behavior. The implementation was corrected to use one fixed
per-family line state, without adding a public line-control or reset surface.
The native path then identified all three units. A separate redacted Python
query was used only as a diagnostic comparator while isolating that timeout;
it was not part of the packaged application or this acceptance path.

## Privacy result

Neither the application document nor its visible summary contained local port
names, USB serial numbers, hardware-instance paths, raw replies, BLE PINs,
MeshCore identities, pairing data, keys, or coordinates. Internal discovery
and transport details were discarded after the reduced result was produced.

## Remaining boundary

Installed runtime identity is not authoritative evidence of the exact received
hardware profile. Processor/memory probing, exact board revision, RF variant,
regulatory fit, bootloader schema, product target role, signed firmware bundle,
write admission, writer, rollback, and recovery remain unresolved. The utility
must continue to fail closed until those gates receive separate evidence.
