# Trail community

Trail is an open-source project for portable and vehicle-based communication
and shared situational awareness. You can help shape it before it reaches a
supported release. Coding is only one way to contribute: clear use cases,
documentation, accessibility feedback and carefully recorded tests also help.

## Join the conversation

Use [GitHub Discussions](https://github.com/Limited-Underground/Trail/discussions)
for questions, ideas and showing what you are building. Use
[Issues](https://github.com/Limited-Underground/Trail/issues) for reproducible bugs
and agreed, scoped work. Read the [current status](../PROJECT_STATUS.md) before
planning a deployment; bench evidence does not establish field reliability.

Start with these discussion categories:

| Category | What belongs here |
| --- | --- |
| Announcements | Maintainer-written milestone summaries and release news |
| Q&A | Setup and development questions; mark useful answers |
| Ideas | Use cases and proposals before they become work items |
| Show and tell | Builds, enclosures and experiments, with clear test limitations |

Please give each topic a descriptive title, search for an existing discussion,
and keep replies constructive and relevant. Do not post pairing PINs, private
keys, device addresses, precise private locations or sensitive logs. Security
findings belong in the [private reporting process](../../SECURITY.md).

## Help wanted

- **iPhone development:** start with the [iOS contributor brief](IOS_CONTRIBUTOR_BRIEF.md).
- **Documentation:** identify an unclear setup step and propose a concise correction.
- **Hardware experiments:** discuss the test first, then record the exact setup,
  observations and limits. Do not assume a candidate board is supported.
- **Usability:** explain the task you tried, what happened and what was confusing.

Read [Contributing](../../CONTRIBUTING.md) before changing code or proposing
large work. Contributions are voluntary unless a separate agreement says otherwise;
there is no promised hardware supply, payment or release date.

## Follow development

Star the repository to bookmark it. GitHub's Watch controls let you choose which
repository activity you receive. The [progress log](../PROGRESS_LOG.md) keeps
detailed engineering history; announcements should summarize meaningful outcomes,
not repeat every internal test or task.

The project aims to earn interest through reproducible demonstrations, clear
limitations, approachable first tasks and replies to useful questions. Community
growth has no guaranteed timetable. External outreach and announcements require
an explicit maintainer decision; agents must not post them automatically.
