## Source-supported explanation and missing discriminator

[TrailActivityController](../../android/app/src/main/kotlin/io/github/nbjelanovic/otclient/TrailActivityController.kt)
sets serviceRequested while an existing-only binding is pending. Its explicit
start method returns while that flag is true. An accepted binding without a
callback can therefore leave the enabled Start button ineffective.

The current absent-service fixture returns null immediately; it does not
exercise an accepted lease with no callback. This control-flow defect is
source-supported and consistent with the physical evidence. The actual Android
binding return/callback state was not instrumented, so unique attribution of
the physical symptom remains unproven. Proposed OT-0304b must first reproduce
the no-callback case against actual controller code before correction; retain
the old source, stale-callback/permission/owner controls and rotation regressions.
