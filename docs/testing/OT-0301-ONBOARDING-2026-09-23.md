# OT-0301 ordered onboarding binding - 2026-09-23

## Result and boundary

The Android Device surface now follows the earliest unverified name/region step
from its actual protected BLE configuration owner. Current-session device
readbacks restore progress after reconnect; phone-local drafts and saved UI
position never establish configuration or authorization. The Ready panel retains an explicit Edit saved name or region control for
ordinary configuration editing. The existing factory-reset settings screen is unchanged.

The host portion is implemented; remaining work is **blocked on public-profile
support and dependency correction**. OT-0301 is not complete or physically accepted. Current
firmware has protected device-name and saved-region readback commands, but lacks
the public-name/visibility command needed to complete the next step. The UI stops
there explicitly and cannot declare setup complete or perform a completion-driven
Messages launch. A saved region is not compatible RF configuration or permission
to transmit. No public discovery, radio transmission, group setup, or new wire
contract is introduced.

The approved scope is [V1 user experience](../product/V1_USER_EXPERIENCE.md).
The parent task owns resolution of the OT-0301 / OT-0302 dependency ordering;
this implementation does not grant an exception or fabricate the missing command.

## Real sequence and failure handling

| Before / owner | Trigger | Required observation | Refusal / recovery |
| --- | --- | --- | --- |
| Device selection / existing scanner | User matches displayed setup label and selects its exact opaque endpoint | Existing selected-device bonding and authorization flow | Label is not protocol identity; no new saved-label authority |
| Pairing / protected runtime | Existing link security, application authorization and mandatory Snapshot | Actual runtime Ready | Reconnect/pairing states expose no verified configuration |
| Name / configuration owner | Read device, then explicitly apply a valid name | Current-session SNAPSHOT or exact applied-name receipt and nonzero revision | Starting a new name read/write clears the prior revision; uncertain result requires a new read |
| Region / configuration owner | Deliberate catalog selection, protected apply, then Read region to continue | Current-session saved-region snapshot with known selection and nonzero revision | Apply alone leaves no reusable revision; missing/uncertain readback stays at this step; no locale default or TX authority |
| Public profile / missing device capability | Name and saved-region readbacks are complete | Protected public-name/visibility implementation is still required | Explicitly blocked, no completion flag or Messages completion transition |
| Interrupted/replaced connection / runtime | Fresh protected reconnect and configuration reads | Fresh name/region observations from that exact session | Previous endpoint, nonce or configuration-owner callbacks cannot apply to a replacement session |

The one automatic region read is bounded per configuration scope and begins only
after a verified name, when the command lane is idle. Failure creates no retry
loop; the explicit Read region control remains available. After Apply region,
the user explicitly reads it to continue. Existing clock behavior is unchanged.

## Implementation

- `V1OnboardingBinding.kt` projects the earliest incomplete step and fences the
  four name/region commands by current Ready state, exact endpoint, nonce and
  configuration owner. Ordinary configuration edits use the same scope fence; a region
  operation cannot precede a verified device name there either.
- `BleConfigurationPanel.kt` renders ordered setup in the actual Ready panel,
  with the existing broader editing surface reachable using Edit saved name or region.
- `BleConfigurationSession.kt` invalidates stale name revision while a new read
  or write is pending. Existing nonce, exchange, revision and result matching
  remain responsible for accepted readbacks.
- The Ready-panel edit toggle is ephemeral and keyed to endpoint, nonce and
  configuration owner; replacing a session starts in ordered setup view.
- No new phone persistence, permissions, storage schemas, background work,
  logging, upload or device authority was added.
