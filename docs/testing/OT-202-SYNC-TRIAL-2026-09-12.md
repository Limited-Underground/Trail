## What the observation establishes

The CRC-checked input record reports 26 discarded bytes, including NUL, SLIP C0
and non-ASCII classifications, and full-frame acceptance after discard. No
anchored rejected frame was recorded. Terminal reason is `none`, first-read delay
bucket is `<1ms`, and the stage result was durably recorded.

`send_return / none` means the bounded send function returned success. It does not
prove host delivery, the evaluation's result, or completion within the host's
deadline; this final stage overwrites the preceding evaluation result.

The host deliberately requests 129 bytes to detect an oversized read and rejects
a return larger than 128 bytes before receipt grammar acceptance. This is
`read_invalid`, not accumulated-buffer `capture_size`. The recorded two reads and
129 total bytes are consistent with an empty read followed by one 129-byte read
under the unchanged code, but per-call sizes were not directly retained. No raw
payload is retained; origin, contents, duplication and any embedded receipt are
unknown. `matching_receipt_observed=false` does not establish that the oversized
block contained no valid receipt.

Host reset-return-to-RUN was 38 ms; reset-call duration was 34,742 ms. These host
intervals and the firmware's first-read bucket have different reference points.
They cannot establish USB delivery latency or physical boot timing.
