# OT-200 bounded input synchronization and durable reasons

Status: **implementation complete; software candidate validated**. The
historical OT-199 physical cause remains unknown. Physical acceptance and
publication remain separate, pending gates.

## Scope and correction

The successor `heltec_v4_security_sync_diag` integrates bounded input
synchronization, one exact diagnostic detail record and an explicitly selected
host decoder. Earlier target images and their source/build evidence remain
unchanged. A malformed anchored candidate can be discarded before a later exact
63-byte command, within finite byte and device-clock budgets. Acceptance flags
latch only after a complete valid command.

The new `input` U64 record preserves both the first rejected-frame reason and
the final stop reason, exact discarded-byte count, first rejected-frame length,
allowlisted flags and a coarse first-read delay. Both reasons are covered by
the same CRC16. The existing `stage` value remains byte-compatible with OT-198;
its legacy loop-limit alias is disambiguated by the new detail record.
Both codecs reject inconsistent field combinations, including success above the
discard budget, acceptance without discarded input, impossible first-frame
counts and incompatible flags. CRC validity alone is insufficient.

Input detail is committed and read back once while the stage is `waiting`,
before committing `input_result` or entering evaluation. Any uncertain write,
commit or verification stops that invocation. These two keys are not an atomic
transaction. A valid detail with stage `waiting` means stage advancement is not
established. A later stage without its required detail is refused by the new
decoder. Old single-key records use the original decoder selected by image;
there is no automatic format detection.

The host's 30-second capture horizon remains a resource bound, never a device
completion guarantee. Parser construction follows startup persistence. The
first-read bucket does not identify byte arrival, FIFO history or host/device
clock skew. Its last bucket also covers unavailable or regressed first samples;
a backward clock sample cannot become a claimed measured delay. A strict
receipt precedes final `send_return` persistence, so those
observations are independent. No new READY/DONE transcript, retry or physical
execution authority is added.

## Validation

The complete affected matrix passed using Python 3.14.6 and native UCRT GCC
16.1.0. The [host validation record](../../tests/benchmarks/crypto/OT-200-INPUT-SYNC-HOST-2026-09-12.json)
retains source hashes, log hashes and per-suite results. Exact commands and full
logs are retained in private task evidence. The ordinary `tools/Test-Host.ps1`
now invokes the same complete affected runner, including generated wire vectors.

| Gate | Verified result |
| --- | --- |
| Synchronizing parser and real receive loop | 61 control groups; includes exact byte accounting and parser-to-codec consistency |
| Packed record and Python parity | 1,435 C++ wire cases checked by the image-selected Python decoder, including CRC-valid inconsistent fields |
| New readback and captured-byte observation | 18 decoder and 9 observation tests; explicit version/image binding and interrupted stage advancement |
| Existing behavior | 24 original control groups; 26 original readback, 17 observation/restoration, 11 timing and 9 strict capture tests |
| Actual application and console composition | 91 scenarios, including 45 storage-failure cases, plus 32 calls through the unchanged strict host capture implementation |
| Firmware | Two fresh ESP32-S3 builds; all seven BIN/ELF/map/configuration/bootloader/partition/OTA artifact pairs identical; zero compiler warnings |
| Source and linkage audit | 43 candidate source pins, 293 repository dependencies, matching external dependencies, 731 verified local library files, preserved OT-187/OT-198 pins and unchanged console routing |

The [build record](../../tests/benchmarks/crypto/OT-200-INPUT-SYNC-BUILD-2026-09-12.json)
pins the final 440,432-byte application:
`25e18eb5f852ea53a005272af13cbbe6fa828833920ecd5c8c79e826984d5a62`.
It uses ESP-IDF v6.0.2, Xtensa GCC 15.2.0, CMake 4.0.3 and Ninja 1.12.1.
Both final build directories were initially absent; cache and dependency
acquisition were disabled. The SDK's NimBLE boolean-default notice is retained
separately from compiler warnings.

Initial sandbox attempts stopped before compilation because the installed
compiler wrapper and SDK ownership require the normal user context. The same
toolchain succeeded there. An initial lifecycle harness compile error and a
missing include in the combined test runner were corrected. Independent review
then exposed the cross-field validation gap; the final source, tests and build
pair include that correction. Earlier failed and superseded logs remain retained.

## Remaining gate

Prepare an image-bound executable observation/restoration package for this exact
candidate and record contract. It must preserve confirmed serial closure, one
durable observation, unconditional independent original restoration and guarded
untouched-role release. The new pure observation API alone cannot execute that
workflow. Existing OT-198 packages and consumed grants do not admit this image.

After package validation, a separately authorized physical trial needs current
device identity, fresh original custody and sequential restoration before the
next device. No hardware, radio, phone, remote Git or website operation occurred
in this increment. Implementation is uncommitted; commit, full required CI and
publication remain pending. The changes do not increase V1 completion or public
website status, select product cryptography or establish a physical USB cause.
